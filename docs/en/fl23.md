# FL2 / FL3: a first-installation walkthrough

[Home](../../README.md) · [简体中文](../zh-CN/fl23.md)

This entry adds FL2 and FL3 Creative Looks to an eligible **Sony A7C II / ILCE-7CM2 with original firmware 2.01**. On Windows, **prefer the CLI**; double-click **`FL23.cmd`** for the original desktop alternative. Both use the same backend. Your own DCP/LUT files use [the independent custom-look workflow](custom-lut.md).

## Prefer the CLI

Preparation, installation, verification and restoration use `prepare`, `install`, `verify`, `restore`. Follow [the FL23 AI reproduction guide](fl23-ai.md) and [command reference](manual.md), advancing only after each step succeeds. Do not chain the whole sequence. Start with help, which does not connect:

```text
.\FL23.cmd --help
```

The desktop instructions below map to the same commands: Backup and check=`prepare`, Install preview=`install`, Verify after restart=`verify`, Restore original=`restore`. Both paths require the same source/backup/power/readback checks.

It changes camera programs and related look parameters. It remains experimental tooling with basic tests on one body, not a Sony-signed updater. This guide explains the normal sequence but does not guarantee recovery from every failure. FL23 device installation uses Windows; [Mac setup](manual.md) is for the independent LUT tool, whose Mac USB path is untested.

## 1. Check the camera and computer

- The camera is **A7C II / ILCE-7CM2**, not A7C, A7CR or A7 IV.
- Its version screen shows **2.01**. This is only the first check; the tool also verifies fingerprints of the actual complete program files.
- The programs are the supported original source. Do not install this over a modified six-look build; differing sources should be rejected.
- Windows has 64-bit Python 3.10+ with the `py` launcher and Tkinter; first launch needs Internet access for dependencies.
- Use a data-capable USB cable, adequate battery and a connection you can maintain through readback. Installation and restoration require an actual battery level of at least 50%.

FL2/FL3/ST capture and playback have worked on one body. Other bodies, long-term use and every shooting mode have not been fully validated. See [the evidence](technical/validation.md).

## 2. Download, extract and open

Download the current [complete a7c2-tools-2.1.zip](https://github.com/QAQLeonard/a7c2-fl23-research/releases/download/v2.1/a7c2-tools-2.1.zip) and extract it; the [Release page](https://github.com/QAQLeonard/a7c2-fl23-research/releases/tag/v2.1) retains attachments and checksums. Do not launch inside an archive preview or extract only a `.cmd` file.

Open `FL23.cmd` in the extracted directory. First launch prepares its local Python environment, then opens the FL2/FL3 interface. Normally, double-clicking is enough. [Manual commands](manual.md) are an alternative for direct use or startup diagnosis; no PowerShell upgrade or execution-policy change is required.

If no interface appears, first check Python, network access and complete extraction. Resolve computer startup problems before attempting installation.

## 3. Connect the camera and prepare USB drivers

1. Set the camera to **USB Mass Storage**, then connect the data cable. PC Remote is a different mode.
2. In [Zadig](https://zadig.akeo.ie/), install **libusbK** for the camera's specified USB identities. If necessary, enable **Options → List All Devices** and identify the target by USB ID.
3. The normal camera identity is `054C:0E8A`. Service connection may expose `054C:0336`, which appears after initial authentication. Each identity needs the matching driver.

Treat USB IDs as device identity numbers. Select only the matching camera; a similar name is not a reason to change a mouse, keyboard, card reader or other device. Installing a driver does not itself flash firmware.

If first preparation stops because the service identity lacks its driver, retain the failed workspace and logs. Confirm that the problem is only that driver and no write has an unknown outcome, then prepare the corresponding driver and resume preparation according to the established state. Do not repeatedly click Install.

### First driver replacement disconnects / “Check the connected device”

A user reported that after replacing the normal driver with libusbK, the initial connection countdown ended with “Check the connected device.” Preparing drivers for both normal and service identities allowed installation to finish; subsequent connections worked. This is a user-reported workaround, not an independently reproduced failure. The code does switch USB identities during initial authentication, but the camera message alone does not identify a driver fault.

| Stage | Common Zadig / Device Manager name | USB ID to verify |
|---|---|---|
| Normal Mass Storage | ILCE-7CM2 | `054C:0E8A` |
| Service connection after tool authentication | Sony USB Device | `054C:0336` |

The camera entering service mode causes the name change; Zadig does not initiate that transition. Its **Replace Driver** or **Install Driver** label depends on the selected device's current driver. **Install libusbK separately for both identities.** Replacing the storage driver may remove the ordinary camera volume from File Explorer; that alone does not mean the tool cannot connect.

Only after all tool I/O has ended, and before any firmware write has begun:

1. If the `ILCE-7CM2` driver binding is faulty, verify hardware ID `054C:0E8A` in Device Manager and uninstall that device. When rebuilding this binding, select “Delete the driver software for this device” if offered. This is troubleshooting, not a mandatory step for every installation; leave other devices alone.
2. Reconnect USB in Mass Storage mode. In Zadig enable **Options → List All Devices**, select `ILCE-7CM2 / 054C:0E8A`, choose **libusbK** and click **Replace Driver** or **Install Driver**.
3. Run only **Backup and check / `prepare`** first. Initial authentication may re-enumerate the camera as `Sony USB Device / 054C:0336`. If preparation stops because that identity lacks its driver, let the command end, then select this new identity in Zadig and install **libusbK**. A working normal driver does not establish a working service driver.
4. Keep the failed workspace and logs. Once confirmed to be a missing-driver failure during preparation only, choose two new empty work/backup folders and run preparation again. Install only after it succeeds. Do not apply this retry procedure after writes have begun, on `needs_review`, or with an unknown outcome; inspect the original job first.

Driver installation is not firmware-installation evidence. If both identities have matching drivers and an error remains, retain the last logs and current USB ID to distinguish busy responses, authentication failure and actual transport errors.

## 4. Fill the two directories and battery level

The interface fields mean:

| Interface field | Purpose | Example |
|---|---|---|
| 機身工作目錄 | Original files, candidates, state and logs for this operation | `D:/CameraWork-A7C2-01` |
| 第二份備份 | A separate original-data copy for this camera | `E:/CameraBackup-A7C2-01` |
| 相機目前電量 | Actual remaining percentage before install/restore | For example `82`; do not copy this value blindly |

For first preparation choose **two different, new, empty directories**, preferably on separate drives. The workspace continues this operation; the second backup keeps an independent copy. Do not select the same folder or clear an old workspace to start over.

Backups belong to this camera and may contain private settings/calibration. Retain them securely; do not upload them, share them as generic firmware or replace them with another body's backup.

## 5. Click 「1 備份與檢查」 — Backup and check

This reads the camera's programs/settings, checks the supported original source, saves both backup copies, builds candidates and runs a native validation-only check. Temporary diagnostics execute, but candidate programs and new saved shooting settings are not installed yet.

Wait for the log. **Done when:** it reports “備份、候選與實機只校驗完成。尚未改寫韌體或保存拍攝設定。” without an error: backup, candidate and native validation completed, with no firmware/settings installation yet. A generic completion status or the appearance of files is not enough.

The workspace contains `state.json`, `original`, `candidate` and other results. Do not edit them: `state.json` tracks progress, `original` retains original data and `candidate` holds prepared changes. Successful preparation has phase `prepared`; it is diagnostic information, not a switch to edit to bypass a failure.

If source, backup or occupied-region checks fail, stop and investigate. Do not change version declarations, remove checks or substitute another body's files.

## 6. Click 「2 安裝預覽版」 — Install preview

Continue only after successful preparation, with the same workspace, the actual battery percentage and continuous USB/power. **This button writes to the camera.**

The tool writes guarded program regions and added look parameters, reads them back for comparison and handles the retained startup image. Readback means comparing data read after writing; it does not test photography.

**Done when:** the log explicitly reports “安裝及讀回完成” without errors. Phase `installed_pending_cold_start` means installation finished and reloading remains necessary. During processing, do not disconnect, switch off, close the window or run another camera operation concurrently.

## 7. Reload after writing has finished

1. Confirm that all tool I/O has ended.
2. Disconnect USB and other power, then shut down normally.
3. Wait for the screen/access lamp to go out. Remove the battery for at least **one minute**, reinstall and switch on. Older tool messages may say ten seconds; this guide consistently uses the longer complete power-removal procedure.
4. Open Creative Look and check for FL2/FL3. If instructed to reset the new looks, first record adjustments you want to retain and use the camera's per-look reset operation; do not initialize the whole camera for this purpose.

This reloads updated storage rather than writing it again. If the looks are missing, preserve the observation and check the actual loaded state instead of clicking Install again.

## 8. Test preview and photos, then click 「3 重開後核對」

First observe the camera separately:

- It enters normal live view without errors or a restart loop.
- Switching ST, FL2 and FL3 on the same scene behaves as expected before pressing the shutter.
- ST, FL2 and FL3 each capture a **new photo** and play it back. Looking at old photos cannot validate new captures with the added looks.

Reconnect in Mass Storage mode, select **this operation's original workspace**, and click **「3 重開後核對」** (Verify after restart). It checks programs, parameters and relevant runtime spans; it cannot judge the actual screen colors for you.

**Done when:** the tool reports “磁碟程式與保存參數符合預期” and the menu, preview, new photos and playback are normal. Record machine checks and physical observations separately. Matching storage alone does not establish complete camera stability.

## Restore deliberately with 「回復原版」

Restoration is a guarded operation, not a universal response to errors. It requires this body's complete verified backups and a supported complete current program source. Unknown or partially damaged sources are rejected.

If you intend to undo this FL23 installation, select ST, shut down normally, fully power-cycle, then reconnect in Mass Storage mode. Select the original workspace, keep the second backup at its recorded location, enter the actual battery percentage (at least 50%) and click “回復原版” (Restore original).

It restores the programs and target settings changed by this operation; it does not repair an arbitrary camera state. Once the log confirms completion and I/O has ended, fully power-cycle again and check live view, new capture and playback. Without service access or complete backups, do not assume this button can recover the camera.

## If something goes wrong

| Situation | Next action |
|---|---|
| Double-click does not open the interface | Check extraction, 64-bit Python 3.10+, Tkinter and Internet access; see manual startup checks |
| Target camera not detected | Check model, Mass Storage, data cable and matching USB-identity driver |
| Initial readiness/busy | The tool waits within bounds; if it fails, retain logs instead of repeatedly clicking |
| Workspace/backup is not empty | New preparation uses new folders; retain old ones. Install/verify continue the successfully prepared workspace |
| Timeout, disconnect, `needs_review` or unknown write outcome | Stop further operations, retain the whole workspace and inspect existing results/state before any rewrite or reboot |
| Programs written but looks missing | Distinguish updated storage from stale loaded state; repeating installation is not a load-state check |
| Camera restarts repeatedly | Stop repeated flash attempts; retain power/connection observations and logs for recovery based on the actual state |

For diagnosis, report the model/version, last button used, last log lines and whether menu/live view still works. Do not publish whole backups or camera files. See [earlier failures](technical/failures.md) for incidents that informed these rules.
