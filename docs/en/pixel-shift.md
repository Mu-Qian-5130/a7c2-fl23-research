# Pixel Shift research — development branch

[Home](../../README.md) · [简体中文](../zh-CN/pixel-shift.md)

Target: the native Sony workflow used by A7CR: tripod, static subject, four shifted RAW captures, then computer composition. Sixteen-shot support is a later goal. Published programs are **offline research, not an installable or working Pixel Shift release**.

On October 20, two owner-authorized three-byte RAM trials exposed the menu but left it disabled. The second used an SD card and still-photo P/M mode, so the missing card does not explain the failure. Both trials were restored and independently checked; neither captured images.

Further disassembly found a separate, undefined C2 parameter-capability entry. The original initializer adds four inhibition tokens for that entry, matching the live read-only counters. Ten ordinary exclusion rules were decoded; none applied to the observed still-M, idle state. A third private trial supplied a C2-native parameter definition and removed only those four unsupported-definition tokens, alongside the menu gate: six AP data windows, 47 bytes. Independent readback passed, but the owner entered an empty submenu before shutting down. Subsequent read-only inspection confirmed all six fields back at their original values; no inverse write was needed. No capture occurred.

The individual submenu options have another model-support table. A fourth RAM trial added off/four support: eight windows, 51 bytes; sixteen stayed hidden. Readback passed, but the owner reported missing icons and later camera errors/blackouts. The volatile tables reverted after power loss while the native four-shot setting remained saved. No capture was reported. The owner subsequently recovered the camera by an unrecorded method. Independent follow-up reads confirmed running mode, RAM Backup and saved Backup all OFF, and the owner confirmed 30 seconds of normal unplugged live view. The candidate remains withdrawn; this is not Pixel Shift or long-term hardware validation. The trial did not edit ROM, CP or calibration, but the native menu did persist a setting. Private device workers are not distributed here.

## Implemented

- [Call-path audit](../../dev/pixelshift/audit.py): resolves Pixel Shift sequence RTTI and actual virtual methods in privately extracted C2/A7CR 2.01 application programs. It checks sequence → wrapper → generic capture packet builder and finds code references to named Pixel Shift routines.
- [Original-instruction replay](../../dev/pixelshift/native_replay.py): four/sixteen-shot selection matches A7CR in 18 paired cases; trigger command `0x4036` matches in 44 paired packet cases. A separate 24 paired cases check the actual capture-activation command `0x4038`, whose six input enums map to different wire values. Selection stops before Bluetooth feedback configuration. Packet replay omits one diagnostic call for `0x4036`, two for `0x4038`, and stops before transport send. Invalid capture enums leave the bounded model without a successful packet. CP admission, exposure and positioning do not execute.
- [Native mode setup](../../dev/pixelshift/trinity_replay.py): the firmware calls Pixel Shift `TRINITY`. Original command `0x40ee` and CP mode assignment match in 20 paired cases, including off, four/sixteen shots, intervals and the native test flag. The CP slice assigns the mode only; it does not demonstrate actuator control.
- [CP command dispatch](../../dev/pixelshift/cp_dispatch_replay.py): 80 paired cases execute the original command table lookup, optional consistency callback, mode handler and parameter-change flag setter on AP-built `0x40ee` packets. Initial RAM and pending-check fields are synthetic; only diagnostic printing is omitted. Transport, the CP scheduler and capture are not executed.
- [CP configuration snapshot](../../dev/pixelshift/cp_config_replay.py): eight paired cases carry that handler-written mode, in the same emulator RAM, through the native snapshot routine and its original ARM `memcpy`. All 3428 copied bytes match. LiRo field `+0x180` becomes capture-configuration field `+0x1a0`; the mode is not assigned again by the test. Other input fields and snapshot arguments are synthetic, and scheduling between the two entries is not executed.
- [Current-settings to TC input](../../dev/pixelshift/cp_mode_source_replay.py): six paired cases retain the dispatched mode through a native 3428-byte current-settings copy, pointer-registry initialization, TC flag update, complete 340-byte input copy, export and 192-byte publication/snapshot. No second host mode assignment supplies the flag. AP selection values 1/2 both encode CP enable value 1. Unrelated settings/context data are synthetic; the settings-copy slice starts after semaphore admission, and task scheduling/delay notification do not execute. This establishes another flag source, not capture-end behavior.
- [CP frame propagation](../../dev/pixelshift/cp_frame_replay.py): 24 paired cases extend that same RAM through the original frame mapper, carrying the mode to frame `+0x98`, then through a later control-flag setter and request-selection slice. The frame's `+0x20` view explains the setter's `+0x78` access. Preparation gates, other fields and branch inputs are outside the replay or synthetic; later request overrides and transport are not executed. The selected value is not an identified actuator command.
- [CP serial-field propagation](../../dev/pixelshift/cp_serial_replay.py): 56 paired cases carry a synthetic frame's TRINITY flag and ordinal through original TC input/copy/index slices, native packing, serial-buffer serialization and checksums. The resulting byte is `(ordinal & 127) | (TRINITY << 7)` at packet `0x39` offset `0x6e`. Native interface-mode initialization controls whether this extension is filled, and a separate flag selects a 100- or 128-byte send descriptor. Tests execute the normal TC branch in one RAM image; other payload fields and interface inputs are synthetic. Full TC calculation, scheduling, serial transfer, the physical peer and positioning remain unverified.
- [Native factory-default loading](../../dev/pixelshift/cp_defaults_replay.py): two paired official parameter banks execute the original BK4 registration, two configuration lookups, complete 256-byte parameter copy, interface decoding and TC branch selection. Both models load interface word `0x0066`, decoded as type 6, which selects the alternate TC branch if later configuration does not override it. Only five void mutex calls are omitted. This qualifies the serial replay above: its synthetic normal branch is not established as the camera's active branch.
- [Factory-selected alternate TC](../../dev/pixelshift/cp_alternate_replay.py): eight four-step paired sequences retain the native default selector in the same RAM, enter the alternate routine through the original wrapper, then publish/read both 32-byte banks. Original code preserves the ordinal, generation and auxiliary word. Inputs, shared flags and scheduling are synthetic; an invalid GPIO port deliberately exercises native rejection before hardware access. This tests software propagation, not a usable GPIO configuration, a live protocol or physical movement.
- [Native ordinal-to-vector slice](../../dev/pixelshift/cp_vector_replay.py): 12 paired steps extend that RAM through original frame-flag export, 192-byte publication/snapshot copies and a TRINITY-gated vector calculation. Ordinals 0–3 produce a four-step raw pattern scaled by three bytes from parameter `0x000f0025`. Both official banks load zero for those bytes; separate nonzero/exponent cases are synthetic sensitivity checks. This conditional producer slice does not execute its preceding mode selection, the complete scheduler, transport or actuator. Physical units and the actual runtime scale source remain unresolved; no scale patch is proposed.
- [Alternate packet/reply validation](../../dev/pixelshift/cp_alternate_wire_replay.py): eight paired cases extend those vectors through the complete original 40-byte packer and native XOR checksum. The vector remains at bytes 4/8/12 and TRINITY at byte 28. Twenty-four paired reply cases check the original type/checksum branch and complete accepted-buffer copy, including rejection without changing the accepted buffer. Replies are separately injected synthetic inputs. No wire transfer, hardware acknowledgment, settling, exposure or centering is verified.
- [Alternate first/second packets](../../dev/pixelshift/cp_phase_pair_replay.py): eight paired cases load the native factory formatter configuration and execute the original first type-7 formatter/checksum before the existing type-8 formatter. Eight further cases with `--full-control` execute the original consumer and complete vector producer in the same RAM before packing; neither formatter replaces the resulting vector or frame snapshot. Both 40-byte packets have the native XOR contract. Stages and unrelated inputs are synthetic/host-invoked; transport and controller feedback do not execute.
- [Controller parameter packets](../../dev/pixelshift/cp_parameter_wire_replay.py): six paired word cases execute official loading of parameter `0x170006`, its native cache-difference scanner, first-phase packing and checksum. Three four-byte words carry coefficient and bias bytes at offsets `0x60/0x64/0x6c`. Defaults and separate nonzero sensitivity inputs are tested; prior cache differences are synthetic. Optional H8 replay validates those packets, executes the complete native parameter-command body, checks exact word writes and then executes coefficient/control-word stores and bias use against shadow registers. Preceding GPIO setup, live adjustment data and physical configuration are not established.
- [Native scale calculation](../../dev/pixelshift/cp_scale_calculation_replay.py): ten paired cases execute the original measurement-pointer initializer, adjustment arithmetic and 72-byte diagnostic record. The three calculated scale bytes stay in the same RAM and feed the complete native consumer, vector producer and both packet formatters for 40 paired steps. An independent rational calculation checks numerical behavior, including zero/negative denominators, the upper bound and byte rounding. Measurement inputs and command admission are synthetic; execution stops before notification and the harness restores CPU registers at that boundary. This is an adjustment-script calculation, not proven normal capture initialization or body calibration. No host assignment supplies the scale bytes.
- [Bonobo controller bridge](../../dev/pixelshift/BonoboBridgeReplay.java): an optional Ghidra H8 replay consumes those actual CP packet pairs, executes the controller's type/checksum/bank-selection prefix, original field getters, TRINITY branch and target-register writer. Sixteen bank/packet cases and 32 corrupted-checksum error-boundary checks passed separately from the Python suite. Register writes land in emulated memory cells; ADC, DSP/PWM, motors, full IRQ/boot and real settling are not modeled. This is a native-code protocol match, not measured movement or physical wiring/calibration proof.
- [Controller reply to CP](../../dev/pixelshift/cp_controller_reply_replay.py): original H8 sampling/encoding produces replies from independently supplied emulated register inputs. Sixteen payloads pass original CP checksum/type validation, complete copying, decoding and signed getters on both models; corrupt checksums reach rejection. Returned words are the signed high 16 bits of the supplied 32-bit register values. Fixture return inputs are independent of target commands; the host does not repair payloads. Peripheral values/framing remain synthetic; receive-side replay does not execute command/feedback timing or verify physical position.
- [Alternate feedback decoder](../../dev/pixelshift/cp_feedback_replay.py): 24 paired cases continue from the accepted reply in the same emulator RAM through its own native decoder and signed getters. Reply halfwords at bytes 4/6/8 are retained; a separate 16-byte context/history copy and the 20-entry ring wrap execute. History inputs are synthetic. This is a different source buffer from the first-phase reply decoder; numerical feedback is not identified sensor-position or settling evidence.
- [Darwin receive/parser replay](../../dev/pixelshift/darwin_capture_replay.py): 276 paired cases execute original message lookup, 34-byte RX-to-stable copying, snapshot retrieval and the parser prefix. Every input bit is exercised; complete snapshots and bounded state writes are checked. RX bytes and initial state are synthetic. No external call is substituted; execution stops before later control calls. Serial reception, the complete CP-to-Darwin bridge, actuator control and sensor movement remain unverified.
- [CP per-frame selection](../../dev/pixelshift/cp_sequence_replay.py): 64 paired cases execute original state-byte getters, the selector and its 17-record descriptor initializer. In mode 23, all four frame ordinals select the same first-column sequence, whereas ordinary mode 2 can select subsequent-frame columns. The test stops before sequence configuration; selected callbacks, exposures and positioning are not executed.
- [CP callback stage dispatch](../../dev/pixelshift/cp_stage_replay.py): 19 paired cases separately invoke those two callbacks with synthetic context stages, execute their original table branches, and stop before the selected child. Seven/eight valid stages and the native invalid-stage return are checked. This maps handler order; no scheduler advances stages and no child performs an exposure or return-to-center.
- [Full native control producer](../../dev/pixelshift/cp_control_replay.py): eight paired frame steps execute the actual alternate-control consumer and complete vector producer, retaining prior vector state rather than supplying a precomputed result. Three more factory parameter blocks load through native code; remaining initial RAM and frame inputs are synthetic. Six host-selected post-request cases show categories 4/5/0 alone retain the last TRINITY vector. Two explicit next-frame-OFF cases switch to independently supplied synthetic fallback targets. Idle publication stops before GPIO. Automatic completion/abort, centering and physical movement remain unverified.
- [Steady timer/wait event](../../dev/pixelshift/cp_steady_event_replay.py): eight paired cases execute the native eligibility predicate, timer callback, original ARM interrupt-context detector and capture wait prefix. Callback and waiter use event `0x2e`, mask `0x80000000`; the timed wait receives timeout argument 10000. Context/frame inputs are synthetic; callback and waiter are invoked separately and stop before RTOS event APIs. No timer fires, wait completes or feedback confirms settling.
- [Capture-status gate](../../dev/pixelshift/capture_gate_replay.py): 102 paired cases execute original `0x4040` request encoding, CP effective-mask/reply fields, AP decoding and its `REQUEST_CAPTURE`/`CAPTURE_NG` event branch. Reply bytes cross a host byte bridge; transports, CP status refresh, reply allocation and event dispatch do not execute. The status inputs are synthetic. Passing this software gate is not sensor-position readiness or a successful capture.
- [CP trigger routing](../../dev/pixelshift/cp_trigger_replay.py): 72 paired cases execute the native AF/AE/AWB rank initialization and arbitration, trigger-message normalization and selected actor routes. The AF preparation route stops before its helper; capture start stops before its handler. AWBL on/off executes its original flag setter. Registries, previous triggers and actor state are synthetic; sender bodies, allocation, transports and actor scheduling do not execute. These tests distinguish preparation/locks from capture and do not emulate an exposure.
- [Sequence/clear boundary replay](../../dev/pixelshift/lifecycle_replay.py): 22 paired cases verify the original still-record factory request, its enqueue gate, the `0x40ef` clear packet and the CP descriptor referring to `TrinityShotEnd`. C2 and A7CR use their own manager addresses. Synthetic state and omitted mutex/diagnostic calls are explicit; execution stops before allocation, construction, transport or the clear service. Neither callback completion nor physical centering is verified.
- [Native group end/release](../../dev/pixelshift/cp_group_end_replay.py): 14 paired cases execute the original caller's callback records, post-allocation factory slice, complete empty-resource constructor and `TrinityShotEnd` through its native vtable release. The original ARM context detector chooses the reference-lock calls; their unused-return semaphore calls are explicitly omitted. The last reference runs empty-resource cleanup and stops before pool return; a supplied resource handle stops before its release API. Other references retain the object, while pending completion callbacks stop before execution. Storage/OS state are synthetic. No real allocation, pool return, resource release, callback completion, RTOS admission or centering is established.
- [CP metadata replay](../../dev/pixelshift/cp_metadata_replay.py): 63 paired cases verify original group-ID, shot-ordinal and frame-count emission into an already allocated six-byte `PixelShiftInfo` field. Frame state is synthetic; no sensor is emulated.
- [CP capture-mode replay](../../dev/pixelshift/cp_capture_replay.py): 63 paired cases execute original configuration selection and TRINITY consistency checks. Given native configuration byte `0xd88`, mode 2 can become mode 23; a synthetic native-state byte can prevent conversion. TRINITY is cleared when the selected mode is incompatible. No capture or actuator call is executed; the AP-to-configuration-byte source remains unverified.
- [CP timing replay](../../dev/pixelshift/cp_timing_replay.py): eight paired cases trace `SetSteadyCapTimer` up to timer creation. The requested delay is the exposure offset minus 9000 microseconds, falling back to one microsecond below that boundary; the callback is `eventCallback_End_Wait_StartSteadyCap`. This establishes a timer-based scheduling path, not a sensor-position acknowledgement. Timer/event APIs are not executed.
- [Capability descriptor replay](../../dev/pixelshift/capability_replay.py): 52 paired cases execute the original model mapping and descriptor reader. C2 model input 16 maps to column 9, where the relevant Pixel Shift support is off. A two-byte change enables this flag in emulation. Live capability caches and hardware are outside this test; no patch file is generated, and an A7CR identity is not guessed from an index.
- [Individual-option replay](../../dev/pixelshift/option_replay.py): 78 paired cases execute the original model-based child visibility getter. Child descriptors use a different field offset from the parent and require the value exactly 1. C2's three rows are hidden; an emulated off/four-only change permits those two while leaving sixteen hidden. This does not execute live permissions, cached state, menu rendering or capture.
- [Parameter eligibility replay](../../dev/pixelshift/eligibility_replay.py): 26 additional original-instruction cases distinguish menu support, a defined parameter and accepted values. C2's permissive fallback accepts values without defining the feature; A7CR defines off/four/sixteen. Replaying C2 initialization with synthetic registries records four inhibition notifications; an emulated native definition removes those requests. The notifier is observed, not executed. The audit also decodes ten incoming rules, retaining restrictions such as AUTO/movie mode, capture encoding and AF-ON.
- [RAW group inspector](../../dev/pixelshift/raw_group.py): reads Sony `PixelShiftInfo` (`0x202f`), checks four unique source shots and exposure metadata, and rejects ordinary bursts, mixed groups and composite images. Passing metadata does not prove physical displacement or compatible composition.
- [RAW displacement measurement](../../dev/pixelshift/displacement.py): compares both green Bayer sublattices, measures fractional translation and checks for a one-pixel square. Independent synthetic scenes pass; no-motion, wrong-spacing and bad-frame cases fail. Real ordinary C2 RAW decoding has been checked, but no real Pixel Shift sequence is available yet. Camera/scene movement can imitate this image evidence; it cannot certify motor position or settling.

The sequence's virtual `run()` addresses are C2 `0x348bcf0` and A7CR `0x348c1b8`. C2 `0x34d1508` calls builder `0x353a260`; A7CR `0x34d19f0` calls `0x353a748`. These are research addresses, not write locations. The generic command is also used outside Pixel Shift. Do not issue it to the camera based on this audit.

The reference-first CP trace now connects mode dispatch to the configuration snapshot and per-frame sequence selection. A7CR's `0x4036` capture request uses destination `0x90040193`, separate from the `0x40ee` parameter destination `0x90030001`. The native frame builder retains one group object across TRINITY frames, and `TrinityShotEnd` resets the ordinal and releases that object. These are software lifecycle facts, not proof of sensor movement or centering. A previously inspected `+0xb8` to `+0x1a0` copy is a configuration serialization helper, not the primary source of TRINITY mode. Offset matches in unrelated structures are insufficient evidence.

The Pixel Shift capture-start helper first makes `0x4040` status checks. Its CP handler returns `0xf000` when the requested mask has no overlap with the effective status bits, otherwise `0xf001`. The AP then posts `REQUEST_CAPTURE` or `CAPTURE_NG`. This identifies a query and event boundary. How the earlier CP trigger and this event's receiver relate to actual exposure still needs tracing. The reply is not an exposure or a motor-settled acknowledgement.

The three native trigger passes have different roles. Trigger 20, used by the inspected `0x4036` builder, can request AE, AF and AWB processing. `0x300e` becomes actor message `0x102` for AF preparation; `0x302e` becomes `0x8307`, whose inspected branch only sets the AWBL flag. Neither is the capture-start handler. A separate `0x300c` packet emits `0x8202` followed by `0x100`; the latter reaches the native handler that calls the configuration-snapshot wrapper. Its sender is behind a separate 14-slot capture registry and status/AF gates. The original `0x4038` AP packet construction is now replayed, and its CP receiver has been located; the complete link from the AP model event through physical exposure is still unverified. Do not substitute a lock message for a positioning command.

The serial trace now shows a concrete combined flag/index field beyond the metadata path. Offset `0x6e` lies outside the 100-byte format. Constructing that byte is insufficient when the extension is disabled or the send length excludes it. Both conditions are exercised with synthetic inputs; the internal interface-mode numbers are not Sony model IDs and do not establish either camera's live protocol configuration. The downstream SIO service registration and dispatcher have been located statically, but the physical endpoint's interpretation, movement pattern, settling and centering still need verification.

Official defaults instead select an alternate TC route that retains the frame ordinal in a buffered control snapshot. Its functional consumer has been located, but its physical meaning is unresolved. Separately, Darwin's 34-byte capture-settings message and parser are now identified. Fields beyond the replayed prefix enter timing/control state; they are not identified X/Y position coordinates. Matching packet sizes alone does not connect the CP sender to this receiver or establish Pixel Shift motion.

The inspected alternate transport has a type-7 first phase and type-8 second phase, both 40 bytes. Their CP reply snapshots are distinct buffers on this paired route; the first-phase decoder is not the legacy 100/128-byte TC format. The Bonobo primary code matches both checksums and the second packet's mode/vector/TRINITY fields. Physical wiring and board initialization remain unverified.

The explicit next-frame-OFF experiment tests feature deactivation, not the normal end of each group. Retaining a vector in a synthetic enabled state does not establish an A7CR bug or a requirement to turn the feature off automatically. The native group-end path resets bookkeeping and releases a reference-counted group object; its release/callback, normal task updates and physical positioning still need tracing together.

## Virtual-machine observations

Experiments using [a7c2-re](https://github.com/chocotan/a7c2-re) run the original AP with limited virtual services. The native menu displayed Off/Shoot 4 Shots and rejected FOUR in Intelligent Auto, leaving mode and virtual Backup OFF. An early forced-menu profile lacked sequence `0x4bd` and later faulted in `sequence_still_record::suspend(NULL)`. A separate normal-boot run did create `0x4bd` with the correct native vtable; a nonzero cache alone was followed through its metadata to verify the ID. Its UI was still black and a MENU input did not advance the frame. Thus the early-profile failure does not establish a missing C2 implementation or the cause of the physical incident. Complete boot, P/M input, FOUR selection, saved-ON/menu-hidden recovery and capture remain unverified. Sensor/IBIS behavior is outside the available model.

A separate guest RAM enable/restore cycle matched all eight original fields after restoration, with mode/virtual Backup OFF throughout. It removed/re-added only the four undefined-parameter tokens while retaining the AUTO counters. This tests the RAM inverse, not saved-ON recovery, flash persistence or physical restoration.

The H8 replay now executes the original BSS zero-init slice to obtain its default override/reference fields, rather than assigning the mode override directly. It does not execute later board configuration. The separate parameter bias and peripheral read inputs remain synthetic. Added stack instruction forms follow [GNU H8 simulator semantics](https://github.com/RTEMS/sourceware-mirror-binutils-gdb/blob/master/sim/h8300/compile.c); the reply helper reads shadow registers, encodes their high words and forms its own checksum. Two SIO framing bytes are fixture data.

The optional third script argument adds four parameter-transfer fixtures (two input variants, two receive banks) separately from the 16 command/reply fixtures. In these parameter fixtures the bias comes through native CP/H8 packet code; the other parameter bytes start as synthetic zero RAM. Byte-shift instruction flags and multi-register stack layout are checked against GNU semantics. These bounded bridges are host-invoked experiments, not a complete boot or an automatically scheduled four-exposure cycle. Factory defaults being zero does not identify the live adjustment/calibration source.

To generate packets from native calculated scales rather than directly supplied sensitivity bytes:

```sh
python dev/pixelshift/cp_scale_calculation_replay.py --c2 private/c2/components --reference private/a7cr/components --output private/calculated-pairs.private.json --h8-input private/calculated-pairs.private.tsv
```

Use `private/calculated-pairs.private.tsv` as the first `BonoboBridgeReplay.java` argument, with a new output path. Its 40 packet pairs produce 80 bank/command cases and 160 checksum-error checks. Peripheral return inputs remain synthetic and independent of those targets. The native arithmetic can round 255.5 to 256 and store byte zero without setting its range flag; the replay preserves this behavior, and does not label an unflagged result physically valid.

`analyzeHeadless` is in Ghidra's `support` directory (`analyzeHeadless.bat` on Windows). The bridge begins after hardware reception with synthetic receive state, stops before later controller processing, and uses native zero-initialization defaults and synthetic calibration/peripheral fields. It neither boots the controller nor replaces a peripheral with a successful hardware response.
