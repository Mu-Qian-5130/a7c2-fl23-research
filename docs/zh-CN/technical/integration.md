## 转换流程

1. 检查 DCP／cube 的尺寸、输入域、哈希和权利。保留 Sony 传感器／机身校准，只提取 look／tone；文件名写着 A7C II 不代表校准矩阵匹配。
2. 用成对线性 RAW／ST 输出及 ISP 响应量测建立 Sony ST 输入模型。固定曝光和白平衡，用独立场景验证；Log LUT 必须提供明确映射。历史拟合只使用单场景和暂定响应，并非完整 Adobe 流水线。
3. 拟合原生有符号 7 位表，报告合成残差、剪裁、中性和肤色表现，保留署名。原生精度不等于完整 DCP 映射。
4. 只导入选中的栏位，配置 ST，保留新鲜的未选配方；分别读取保存和运行绑定。菜单仍可编辑，并没有硬锁 ST。
5. 使用精确来源适配器。六表更新只改所选表和校验值；完整六款程序构建要求固定的历史三款输入。未知哈希停止，后续更新必须审查新的来源身份。

## 离线适配器

在解压后的工具根目录执行。下列命令只准备私人文件，不连接 USB。

| 命令 | 精确支持的来源与产物 |
|---|---|
| `prepare-transition --layout three-preview-v2` | 固定历史三款来源，仅替换栏位 1–3 数据 |
| `prepare-transition --layout full7-v4` | 固定六款来源，仅更新选中的栏位 1–6 及对应校验值 |
| `prepare-preview-retry` | switch-v2 → v4 的三个指令窗口，共 44 字节，不改色表和 AP |
| `prepare-six-program` | 历史三款 preview-v2、固定原生 FL23 CP 和六张私人表，生成受保护的 full7-v4 程序 |

```text
python lut.py prepare-preview-retry "D:\MyLook\appFw.so" "D:\MyLook\switch-v2-cpapp-b.bin" "D:\MyLook\preview-transition"
python lut.py prepare-six-program "D:\MyLook\six-candidate" "D:\MyLook\three-appFw.so" "D:\MyLook\three-cpapp-b.bin" "D:\MyLook\fl23-cpapp-b.bin" "D:\MyLook\bindings.json" "D:\MyLook\six-program-transition"
```

六款程序命令输出正向／还原清单及 `integration-required.json`，不配置 68 份资源文件、新鲜 ST 设置、原生交易或保留启动镜像。未知来源哈希会停止；更新色表会改变 CP 身份，后续更新需要重新审核适配器。退役的无保护 `bootstrap6.build` 拒绝执行。校准、拟合和数据更新命令见[手动说明](../manual.md)。

## 名称、设置与实时预览

名称资源独立于程序。本机使用 68 份语言／布局文件，栏位顺序对应 ID `0x0200ab2d/ab2c/ab2e/ab2f/ab30/ab31`。保留 ID 和布局范围，核对原生读取器；不要公开原始资源或机身备份。部分导入时，未选栏位必须保留原生动态名称读取。旧三款静态命名曾误使 4–6 显示 ST，不能因目前六栏均已导入就认定旧行为正确。

FL2／FL3 接入原生 mode／gamma／chroma／matrix 路径，其预览正常不证明新 LUT 已进入实时取景。root+1 是处理上下文字段，不能一概等同于视频／照片；gamma 域参数必须分开。

v4 仅修改预览路径，共 44 字节，文件偏移／长度为 `0x13553a/4`、`0xb2750e/18`、`0xb27578/22`。对校验通过的导入 root0 缓存表，缓存命中后复用原生 `0x23d56c` 请求再次上传。上传器 `0x42cd28` 先检查 state+`0x24`，再由 `0x78aa20` 复制打包的 1,620 字节 bank。模拟中漏掉一次提交可能已推进标签却未上传，后续帧便保留旧色；v4 在不重建 bank 的情况下重试。这不是实机调度轨迹。

每次符合条件的预览更新都可能重传，不只是切换栏位时。十次相同受控更新中，旧版上传一次，v4 上传十次，两者均只构建一次。性能和功耗必须量测，不能承诺可忽略。保留 switch-v2 对跳入 B.W 指令后半部的入口修复；不要恢复已撤回的 4 字节 `0xff2f04` 通知试验，其标志未被证明是纯预览失效通知。

## 经授权的设备写入前后

写前获取新鲜完整程序、两个设置域和受保护校准，分盘保存两份已核对备份，不用旧快照替换当前配方。要求精确机型／固件／来源、持续足量供电、完整文件前置条件、已测试还原及原生只校验。名称、程序和设置分别作为可审查交易。

同一时间只运行一个服务会话。LUT 层在认证前绑定普通 USB 序列号哈希；仅已知初始忙碌状态或标准无卡 sense `02/3a/00` 允许一次服务连接，写入前仍须核对完整程序和原生型号。HASP 响应不能当作稳定机身 ID。超时、断线或原生结果未知时停止，检查已有结果／临时文件，不要重跑写入。恢复也需要普通 USB 身份。不要仅因超时就重装驱动；FL23 通讯保持不动。

写后核对完整文件、大小／inode、只读挂载、已知临时文件清理和新鲜设置保留。设置检查覆盖可写 AP 组 `02cf`（已知诊断值 `02cf0b6e` 除外）及四个受保护 CP 单元；其他运行期组保留备份，不比较也不写入。缺少字段、属性变化、未选 AP 设置变化和校准差异仍会停止安装。保留启动镜像另行处理，先查实际模式；已经是 mode0 时不要盲目重跑预期 mode2→0 的程序，也不要重复刷写来迫使旧运行态重新加载。

所有读写结束后，才请求一次必要的完全断电重载。分别核对 AP 运行片段、CP 完整磁盘文件、保存／运行配方、保护单元和启动证据。内核启动或文件哈希不等于正在执行的 CP 指令证明。再分别检查不按快门的预览切换、新照片／回放以及原有 FL／FL2／FL3；照片正确而预览卡色是可能同时存在的状态。
