# 历史错误与必须保留的保护

[返回首页](../../../README.zh-CN.md) · [English](../../en/technical/failures.md)

这里记录已经观察到的错误；扩展导入流程时必须保留这些教训。

| 事件 | 已确认事实 | 必须采取的做法 |
|---|---|---|
| 显示试验导致循环重启 | 离线检查和完整读回通过，进入拍摄仍重启；具体崩溃操作未证明。本机用 AUTO 并立即 MENU 后成功还原 | 不复用失败的显示跳板／段／图标库方法。界面、预览、色表分开改，保留精确原档及已知可用备份；AUTO 不保证恢复 |
| 右侧名称空白 | 两轮早期字符串／显示尝试造成空白 | 验证实际资源／原生读取路径和运行加载，不把字符串写入等同于可见名称 |
| 未导入的 4–6 显示 ST | 旧三款静态命名误影响仍可切换基础外观的原生栏位 | 静态名称只作用于导入栏位，其他保留动态名称和配方；有意导入六栏是另一范围 |
| 照片正常但预览卡色 | 机主多次确认照片正确、取景偶尔停在上一款 | 分开测试不按快门的预览和照片；不要为预览传输／缓存问题重拟合、重写已工作的色表 |
| 分支跳入 B.W 中间 | 受控非零 root+3 快照路径进入被替换宽指令后半部 | 保留 switch-v2 修复，审计所有入口及 ABI；root+3 的产品语义仍未确定 |
| 撤回 4 字节通知试验 | 消费者跟踪未证明纯预览更新标志，测试曾把外部例程替换为桩 | 冷加载测试前先还原，不重新启用注册字 `0xff2f04=0` 作为预览修正 |
| 磁盘更新但运行旧镜像 | 早期 RAM 核对显示 AP 仍为旧标志 | 检查实际加载状态，所有读写结束后再按需完全断电；不要重复刷写解决保留状态 |
| USB 未就绪／忙碌／超时 | 初始身份查询存在明确就绪／忙碌，也出现未知结果 | 仅对已知初始只读状态有界重试；超时／断线／未知写入结果停止，先检查或恢复既有结果 |
| 内存位置假设不安全 | 早期 helper 位于不可执行或重叠 BSS，填零 rodata 也有引用 | 证明加载、地址变换、可执行／可读范围、引用和生命周期；页面权限不是内容实际加载证明 |

v4 重传策略增加重复工作，当前正面观察不证明长期性能或排除全部原因。保留精确逆向清单，实机观察单独报告；不要把优化与名称／色彩改动混在一起。

不能把别人的校准或完整备份写入另一台机身，也不要从过期快照回滚无关设置。完整固件／参数读回只验证字节，不验证真实启动或色彩一致性。私人失败记录应保留，但不能公开序列号、照片或校准。
