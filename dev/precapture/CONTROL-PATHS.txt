# Native control-path comparison (offline)

This branch does **not** implement working camera pre-capture. This audit
identifies original code that can inform an implementation; it generates
private evidence and never connects to or modifies a camera.

Run with Capstone and private original firmware:

```text
python dev/precapture/audit_control.py --firmware-root PRIVATE_FIRMWARE_FOLDER --output NEW_PRIVATE_REPORT.json
```

The audit pins both CP image hashes, checks actual instructions and direct
branches, decodes the original priority branch tables, and checks task names,
ID arrays and configuration records. All code addresses below are **file
offsets**; firmware pointers have a separate `0x108000` load bias.

The target S1 controller calls its original start wrapper at `0x3ad540` and
`0x3ad5ae`, and stop wrapper at `0x3ad4c6` and `0x3ad5ea`. These paths are
present; they are not evidence that stock A7C II already acquires pre-S2 photos.
The separate AP settings/switch entries and CP `0x4172/0x4173` handlers remain
stubs, as established by the earlier audit.

Request storage is different: the donor selector scans 15 entries at a
20-byte stride; the target scans 14 at a 16-byte stride. Request 13 has the
highest priority in both recovered tables (13 and 12 respectively). Donor
arbitration additionally preserves/special-cases request 13 around
`0x396dba`, `0x396f60` and `0x396f94`. The target has different special
notification handling (`0x350aa4` onward). Do not copy donor object layouts
or assume identical request semantics throughout the pipeline.

## Queue-task ownership

The donor task-name clue now has a corresponding configuration and object
binding:

- Task ID 174 (`CAP_PRECAP_CTL`): descriptor file `0xe69c90`, entry pointer
  `0xbd879d`, stack size `0x2000`. Kernel task setup at `0x532480` onward
  indexes the descriptor array using `(task_id - 1) * 40`.
- Constructor `0xa9dce4` binds task ID `0xae` and message queue `0x51`
  to the task object at VA `0x192aecc`.
- Startup `0xa9dab2` passes that object to `0xad07d6` using a tail branch.
- The shared entry `0xad079c` retrieves the runtime callback object; its
  configured callback is the generic message loop at `0x4585e8`.
- Queue configuration/event producers at `0x3b8c00` / `0x3b8c60` enqueue
  callbacks to this task. Thus the task name alone does not identify a
  sensor-start routine.

The target already schedules its Timeshift queue through a different owner:

- `0xa0589e` starts the task object at VA `0x1a3aae0` and passes it to
  `0xa09a8e`, which stores it at VA `0x1a45ca4`.
- Constructor `0xa05d8e` configures task ID `0x88` and queue `0x38`.
  ID 136 maps to `CAM_CAP_MGR`, with descriptor file `0xdab60c`,
  shared entry pointer `0xb435a3`, and stack size `0x2000`.
- Original queue configuration/event producers `0xa09aee` / `0xa09b34`
  load this stored owner and call callback enqueue `0x407f1c`.

This resolves the original owner of the **existing target retention queue**.
It does not establish that new sensor work can run in that task context, or
resolve the missing asynchronous `0x4173` enable path. Preserve the native
callback lifetime, queue failure handling and OS protection.

## Remaining implementation boundary

Trace the capture-message receiver and its pre-S2 sensor/driver sequence,
identify actual pixel buffers and their lifetime, and connect settings,
enable, S1/S2, retention, recording and cancellation without disturbing
ordinary shooting. Native queue capacity is metadata capacity. Offline
matching and valid readbacks do not establish camera boot or shooting safety.

No flashable candidate has been produced from this audit.

## Capture-path continuation

audit_capture_path.py pins the original instructions and decodes both TBH
dispatch tables for the following new findings:

- Capture command0x300c reaches donor0x3f7e9a / target0x3ae144. Both
  construct internal0x8202 followed by0x100, with original context and
  request parameters. Target queue900302d9 has an original receive loop
  at0x3ae698 and virtual dispatch at0x3abe90. This establishes the next
  message layer, not physical sensor activity.
- Donor0x8205 processes a full S1-info word at0x3f6e02. Target0x8205
  processes a two-word pressed/index update at0x3ad1ba. Target0x8206
  also has an existing, different handler at0x3ad1d0. Event IDs and
  payload layouts are not interchangeable across the two firmwares.
- The target gate0xa2f0fa returns0 outside its debug-override branch.
  Original producer0xa06126 stores its result at private-context+0xd97.
  Parameter getter0xa061a4 returns context+8, so consumer0x36d8ae reads
  that same byte as parameters+0xd8f, then writes frame+0x66e8=2 when
  it is set. The donor uses context+0xf47 / parameters+0xf3f instead.
- capture_gate.c reconstructs donor0xac4b0a and the donor producer's
  context+0x10 guard. Native leaf/producer/consumer instructions were
  executed offline, with no successful allocator, OS or transport mocks.
  AArch64/Thumb compiled predicates match the donor instructions.
- Donor master+0x138 is the enable state. The target uses that master
  offset as the mode source copied to context+0x160. Reusing donor
  stores there would overwrite an unrelated target field. A runtime
  state owner is still required before installing the new predicate.

## RAW allocation boundary

Target prefetch routine0x3708e8 calls0x408870. That service client
constructs request0x20 with operation0x55, checks reply0x8020 and status,
and copies a0xd8-byte descriptor on the accepted path. Descriptor reads
include a buffer ID, record count and address/size records. These are
separate from the 500-node Timeshift metadata pool.

Target frame allocation0xa04f28 calls0x37019c and stores its ID at
frame+0x5ad8, address words at+0x5eb0/+0x5eb4 and size at+0x5eb8.
Its caller is0x392e92. Release0xa04fe6 calls0xa13a60 ->0x408fdc
(request0x23, operation0x55), invalidates the ID and clears descriptors.
Donor allocation0xa98eb6 instead uses frame+0x5c60 and extra wrappers.
Those wrappers0xa948c0/0xa948d0 end in0xa94544/0xa94546, both BX LR.
They are no-ops, not evidence of extra reference counting. Do not transplant
the donor fields or release routine; the rest of lifetime handling differs.

Original target stage0xa0dd98 submits the instance to the retention
queue via0xa09b34. Its surrounding scheduler/lifetime calls still need
to be connected to RAW ownership and the later release path. No native
RAW service was executed and no RAW pixel contents were acquired in
these offline runs. Real capacity must come from the actual configured
pixel pool, not the metadata-node count.

## Deferred control, completion, and capture-mode ownership

Target AP sender file/ELF VA0x35358b8 is now identified. The compiled
ap_transport.c constructs native setting/shooting requests with that sender
provided by its caller. Actual process load bias, hook placement and domain
dependency are unbound. The offline run stops before the sender; it never
manufactures a CP completion to make an AP request look successful.

Donor0x4173 handler0x277488 records command/context/origin then submits an
asynchronous change. Target origin accessor0xae402a reads message-12.
Donor apply event0x8207 at0x3f6eec defers while native context+0xc is busy;
when idle it commits master+0x138, calls native release0xaaf58a, then
completion0x843ac2. The reply is12 bytes, status0xf000; its sender counterpart
is target0x7d2a14. That sender filters origins in BF/DC domains and reaches
native message allocation/copy/send through0x3abc48. Neither sender nor
release/requeue executes in the control-state tests.

cp_control_state.c uses32 independently owned bytes, with explicit pending
and committed-but-not-completed stages. It cannot return from stage2 to
idle without a future real backend completion. It supplies no allocation,
OS locks, native event interception, scheduling or successful ACK shortcut.
verify_cp_control.py checks these primitives against original donor stores,
pending metadata, busy leaves and commit boundaries on both architectures.

trace_capture_modes.py traces the target AP0x4014 packet, CP handler table
entry at file0xff2d80 ->0x24d650, and stores at0x24d724 onward. Original
memcpy0x51660c copies the complete0xd64-byte master region into private
parameters+0x28. Thus master+0x138 becomes parameters+0x160. Forty synthetic
cases execute this actual store/copy chain. The AP request mode1 branch
generates raw mode1 or0x1a depending on its option+8; these are capture-mode
values. They do not establish an electronic-shutter restriction. AP replay
stops before its first conversion dependency and does not send a request.

## S1/S2 boundaries and coexistence with existing custom looks

trace_shutter_edges.py executes original target incremental button handling
for S1/index1, AF-ON/index18 and combined selections. It stops before the
original start/stop helpers. Record-reference construction skips subtype13;
other tested subtype1 changes enqueue callbacks0x36cfac/0x36d014 to the
existing ownerVA0x1a3aae0. Callback construction does not deliver a shutter
event or preserve a real image. Capture-end callback0x36d070 ->0xa058b6
constructs a special marker3 instance, which queue handler0x371fc8 maps to
event4. Full cancellation/lifetime coverage remains open.

The current six-look CP readback was identified and its code hash matches
the earlier v4 fixture; LUT contents remain variable. It has only80 bytes
of geometric text-tail padding. With verified Thumb output the two capture
predicates total90 bytes (the earlier ARM build was148 bytes), so
simply appending them there is invalid. verify_extension_layout.py explores
a mapper wrapper and an executable final rodata page, in an offline MMU

safety, copy/cache order, ownership, or permission to use padding.

prepare_native_probe.py emits only a NON_INSTALLABLE JSON experiment plan
for seven bounded substitutions using original S1/count-policy code. It
never saves modified firmware or emits an installer manifest. Native

Device work remains scoped: backups and temporary read-only diagnostics;

## Native S1 predicate, deferred backend, and recording handoff

s1_trigger.c reconstructs donor0xaad012. The mask dependency previously
called raw master+0x86c is SET_S1AF: both models register command0x4064.
Donor handler0x278938 stores the byte input as word master+0x86c; target
handler0x24ed40 stores it at master+0x700. Both original stores execute in
verify_s1_trigger.py. The target adapter reads only its proven mode+0x138
and S1AF+0x700, with independently supplied enabled/trigger state.57,600
synthetic vectors match the donor in the general predicate and target
adapter on each compiled architecture. No physical button event is sent.

The native S1 deferred ring is20 slots x28 bytes with capacity19. Target
enqueue0xa17eae matches donor0xaac5ee byte-for-byte; target pop0xa17f02 and
peek0xa17f60 are also reconstructed. deferred_queue.c preserves the native
empty sentinel and refuses full queues.400 index combinations per operation
and190 FIFO transactions per compiled architecture execute the original
target routines, including its ARM bzero. These are local ring operations,
not OS task delivery, and require the existing owner to serialize access.

cp_backend.c now links parameter/control state, the S1 predicate and proposed
prepare/apply event handling to caller-supplied native functions. It uses
checked request sender0x3abc48 and internal post0x3adfe4; release precedes
completion reply0x7d2a14. Native command0x403d pairs cancel/release reason4;
0x4038/4039 uses request subtype13. Explicit send failures preserve a fault,
and a failed release is not automatically repeated. The48-byte backend
state includes requested activity and generation. S1/button/capture-end
interception and exclusive state ownership are NOT installed or established.
Proposed event0x8240 is rejected by unmodified native routing. Do not send it
to a stock or current camera. verify_cp_backend.py stops at9 native request,
post or release boundaries and executes3 real native ring deferrals; no
successful send, ACK, cancellation or sensor callback is mocked.

trace_request13_handoff.py executes24 target cases. With request13 active,
normal start at0x350aa4 bypasses insertion of a competing capture request and
constructs0x3026(enabled=1, subtype, context, timestamp); normal stop at
0x350e60 constructs enabled=0. Stopping subtype13 itself takes0x9da59e.
The native bridge0x3ae2aa copies notification fields to event0x8203; existing
record-reference callbacks reach CAM_CAP_MGR. Timer reads, sends and
callback enqueues are stopped before execution. This identifies the native
pre-capture/formal-recording handoff, not acquired pixels.

frame_route.c matches dequeue metadata stores0x372486 onward and native
route selection0x37e046.320 combinations per architecture preserve RAW IDs
and distinguish the native error class1 from class2. Record routes4/5 and
discard route6 are actual dispatch choices, not saved/deleted photos.
The native route6 descriptor begins8; its stage6 dispatch eventually reaches
bulk cleanup0xa1071e. That routine scans35 IDs at frame+0x5ad8 and calls
0x36c2ac for valid entries; the latter uses native RAW-release service before
invalidating IDs/clearing matching descriptors. Scheduling, real RAW
ownership/backpressure and cancellation still require end-to-end evidence.

## Code-generation correction

Zig0.13 with arm-linux-gnueabi plus -mthumb emitted ARM functions. Earlier
compiled comparisons established32-bit ARM semantics, not the claimed Thumb
ISA. The new thumb-linux-gnueabi target and explicit CPU feature exclusions
produce real Thumb function pointers and no FP/SIMD dependencies. Every
generated ELF is checked through its ISA mapping symbols, excluding literal
pools; wrong ISA, FP/SIMD and missing symbols are rejected. Old ARM and old
Thumb-with-NEON artifacts were confirmed rejected. Codec, retention, capture
gate, CP control, AP marshalling, S1 trigger and deferred-ring suites have
been rerun with these checks. No research ELF has been uploaded to a camera.

The full linked backend is larger than the geometric rodata tail. Neither
zero padding nor existing functions are approved storage. Executable
placement, real boot loading and all live task hooks remain unresolved.

## Existing native parameter path: no ROM modification

The target debug-root pointerVA0x1a533a4 is the first item of tableVA0x110fc88.
The corresponding first key in both variant lists0x110fcd0/0x110fd10 is
CP0x00030072, with size256 in table0x110fd50. Initialization0x3b0b58 loads
the list; update path0x3b1008 reloads selected entries. Registered callback
VA0xb2591b (file0xa1d91a) copies the supplied value to its registered
destination. The original copy instructions execute in
audit_native_debug_parameter.py with guards around the256-byte destination.

An offline candidate changes bytes F0:00->10, F1:00->11, F3:00->02; F2 stays0.
It uses existing S1 debug triggering and a count policy with2 metadata
references. Original, unmodified target gates/edges/configuration execute
with those bytes. The script outputs private evidence and an exact inverse;
it has no USB or write command. This is not the normal configurable port.

On one connected ILCE-7CM2 2.01 body, a separate private operator was
explicitly authorized to write/restore this single parameter. The unit was
read first and backed up twice. After writing, all256 bytes read back as
the exact candidate;53,242 other RAM properties were preserved with2 known
runtime counters, and all53,245 saved properties were unchanged. Both
complete AP and CP file hashes remained unchanged. No save/reboot command,
temporary plugin or ROM-writing API was used. These facts establish the
parameter transaction, not live debug-root contents or physical pre-capture.
The physical attempt FAILED: half-press caused a stall, crash and automatic
restart, as reported by the operator. Do not repeat these candidate bytes.
The subsequent recovery check read the entire unit at its original all-zero
value; both complete AP/CP file hashes still matched their pre-test hashes.
Thus no restore write was performed. The operator subsequently confirmed
normal shooting/playback. This is not a persistence guarantee for another
camera or acceptance of pre-capture. The specific failing native
operation remains unidentified; prior offline tests stop before the real
sensor, allocation and task-delivery boundaries. Pre-trigger photos and
actual pixel lifetime remain unverified. There is no releasable feature.

## Existing diagnostic-log route

audit_log_read_path.py pins the original libsencore and executes its
category0x601/command0x23 dispatch to function0x11b50. With selector0 and
internal input state1, it selects /proc and /proc/klog, then helper0x10a98
operation8. The helper branch table selects0x10d80, which reaches the
actual fopen PLT entry0xaab0 with a native mode prefix beginning r. The
following initialized word is-1, so the audit explicitly records72ffffffff
and does not assume an r-NUL string. It stops before fopen, with no supplied
OS success. Native code counts until EOF before its size check; bounded
USB transport is not proof that an arbitrary proc read cannot block the
service. This identifies a diagnostic route, not a validated crash reader.

The optional pinned-kernel audit resolves the proc registration at0x5bced0
to file operations0x61e068: read0x130fe0,writeNULL,open0xb8398. The latter
binds sequence operations0x61e048; show0xb83c0 dispatches through the native
ring reader0xb87c8. Six post-lock/input cases execute the original capacity
comparison at0xb882c, stopping before copy0xb85c8 or unlock0x423c80. A cursor
at/beyond capacity requests no copy; other cases cap it to the remaining
capacity and caller length. No ring-lock or hardware read is simulated as
successful. This strengthens the bounded-reader evidence without proving
the live buffer's size, contents, preservation or crash origin.
