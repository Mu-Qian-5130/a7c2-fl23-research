Offline pre-capture protocol prototype

This is an implementation experiment, not a camera feature or installer.

Current continuation includes S1 triggers, deferred-ring primitives, native
backend boundaries and recording/RAW-routing traces. No pre-capture code
has been installed on a camera. See CONTROL-PATHS.txt for evidence/limits.
offline_codec.c implements setting/shooting message encoding. It contains no
USB access, firmware hooks, hard-coded target state address, or constructor.
The ELF files generated by verify_offline.py are local emulator test inputs.
Do not rename them libJit.so or send them to a camera.

Reproduce with private original research inputs (never distribute firmware):

python -m pip install unicorn capstone pyelftools
python dev/precapture/verify_offline.py --firmware-root PRIVATE_FIRMWARE_FOLDER --zig PATH_TO_ZIG --output NEW_PRIVATE_OUTPUT

The firmware folder must contain the original a1ii-4.00/components/appFw.so
and cpapp-b.bin with the pinned fingerprints. Zig 0.13 was used.
No complete firmware or generated artifacts belong in this source directory.

262 checks passed: native AArch64 and Thumb encoders, 20 durations, 3 triggers,
2 modeled domain values, 4 shooting combinations and 7 invalid-input cases
per architecture. Valid payloads match execution of the actual original
donor conversion instructions. Their domain dependency is explicitly
modeled as 0/1, not established as a usable A7C II runtime field.

Still missing: target AP runtime placement, CP runtime state ownership and async
scheduler binding, image buffer allocation/lifetime, S1/S2 synchronization,
frame retention, save/cancel handling and physical acceptance. Do not infer
that this code implements pre-shutter photography from codec test success.

预拍摄离线原型：已实现编码、门控、控制状态及部分保留策略，仍不是预拍摄成品，没有刷写入口。
262 项检查验证两种架构的编码与供体原始转换指令一致，不证明实际拍摄链已连通。
相机端调度、缓存、快门同步及存盘／取消尚未实现；不要把测试 ELF 上传相机。

Second-stage queue work (still offline, no installer):

retention_policy.c implements target-matched pending-frame pruning,
post-trigger discard decisions, empty/idle-only policy configuration and
reference sequence/timestamp latching. It does not allocate pixel buffers,
acquire camera OS locks, provide sensor frames or physically press a shutter.

python dev/precapture/verify_retention.py --cp PRIVATE_ORIGINAL_CP --zig PATH_TO_ZIG --output NEW_PRIVATE_OUTPUT
python dev/precapture/verify_storage.py --cp PRIVATE_ORIGINAL_CP --output NEW_PRIVATE_OUTPUT

3,186 native/compiled comparisons and configuration guards passed across
AArch64 and Thumb. Oracle decision tests stop before the original dequeuer;
they do not invent successful frame saves or frees. The reference latch is
executed directly and compared byte-for-byte, including untouched fields.
The original node-pool initializer and original ARM memory clear were also
executed: 500 linked-list nodes, 12 bytes each, with an empty52-byte queue.
This count is metadata capacity, not500 full-resolution image buffers.

Real target firmware hooks, context/OS locking, sensor preS2 readout,
actual S1/S2 event delivery and final recording/cancel remain unbound.
Existing FL23 and LUT implementations are untouched.

capture_gate.c now provides the donor-matched normal enable predicate and
its frame-context guard. Original target instructions demonstrate that the
stock ordinary gate is disabled, while its downstream metadata consumer
still accepts the Timeshift marker. Both compiled architectures match the
original donor leaf/producer instructions. This does not acquire images.

The capture audit identifies native request translation, differing S1 event
payloads, and RAW service allocation/release paths. Never transplant donor
event0x8206 or master+0x138 writes: the target uses them differently.
Runtime state storage, physical sensor timing, pixel retention ownership and
capacity remain unresolved; no flashable candidate is provided.

ap_transport.c reaches the native sender call boundary with actual donor
codec outputs (22 cases). cp_control_state.c uses independent state and
keeps request acceptance separate from idle commit and real completion.
Its two-architecture tests compare26 parameter stores,64 pending/busy/commit
cases,30 invalid/stage guards and16 original reply-builder boundaries.
The native queue/release/sender operations never execute in these tests.

The capture-mode trace executes40 AP-encoding/CP-store/parameter-copy cases,
including original ARM memcpy. This confirms that the target mode field
would be corrupted by copying the donor enabled-field store. It does not
identify a usable electronic-shutter setting or acquire pre-shutter photos.

The S1 trace checks96 button edges and16 record-reference cases, stopping
before start/stop or enqueue. See CONTROL-PATHS.txt for the actual callbacks,
deferred completion ordering and the correction of donor no-op wrappers.

The backend links independent state and trigger logic to checked native
message operations, with faults, busy deferral and stale-event rejection.
Its proposed event interceptor, capture-end synchronization, real task
serialization, queue policy hook and code placement remain unbound. The
tests never fabricate successful native send/sensor returns or a final ACK.

Code-generation correction: Zig0.13 previously emitted ARM despite
-mthumb. All relevant suites were rerun using thumb-linux-gnueabi and
explicit integer-only code generation. The common ELF loader now verifies
Thumb symbol tags and mapping symbols and rejects FP/SIMD instructions.
Earlier semantic comparisons were not proof of Thumb ISA or boot safety.
The two gate bodies are90 verified Thumb bytes, exceeding80 available text
tail bytes; the complete backend is larger still. No installable placement
or live end-to-end pre-capture result is claimed.
